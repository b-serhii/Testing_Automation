# Лабораторна робота №7 — складні UI-сценарії (варіант №1)

Навчальна дисципліна «Автоматизація тестування». Оригінальний стенд: https://the-internet.herokuapp.com.

**Продовження ЛР №6 за технологіями:** Playwright Test + TypeScript, але нова адреса стенду, інші сторінки й нові тести. Підготовлено окремий Git-репозиторій із гілкою `lab7-variant1`; історію ЛР №6 не підмінено. Для публікації у тому самому GitHub-репозиторії наявна інструкція поруч із ZIP.

## Встановлення

```bash
npm install
npx playwright install chromium
```

## Тести

```bash
npm test                            # 17 основних сценаріїв у Chromium
npm run test:variant               # два незалежні сценарії варіанта №1
npm run test:forms                 # 3 тести форм
npm run test:tables                # 4 тести таблиці
npm run test:dialogs               # 3 тести діалогів
npm run test:files                 # 2 файлові сценарії
npm run test:tabs                  # 2 сценарії вкладок/фреймів
npm run test:dynamic               # 1 сценарій динамічного вмісту
npm run typecheck
npx playwright show-report --port 9325
```

Додаткова перевірка у Firefox (не вимагається конфігурацією прикладу лабораторної №7):

```bash
npx playwright install firefox
CFFIXED_USER_HOME="$HOME/.playwright-firefox-home" npm run test:firefox -- --workers=1
```

Важливо: у попередній лабораторній №6 на macOS Firefox вимагав окремих змінних середовища. Якщо помилка `Could not find profile folder` повториться, скористайся блоком з інструкції запуску.

## Заміна адреси стенду

Для стенду викладача підтримується `BASE_URL`:

```bash
BASE_URL=http://localhost:3000 npm test
```

**Жодних `waitForTimeout` у тестах немає.** Для очікування станів застосовано `await expect(locator)` і події браузера, підписані до дії. Кожен тест починається в незалежній новій сторінці.

## Знімки екрана для звіту

Після реального успішного запуску на твоєму Mac додай знімки:

1. Terminal з підсумком `17 passed` (якщо всі тести пройшли).
2. HTML-звіт із результатами всіх тестів.

У середовищі, де підготовлено роботу, npm registry та зовнішня навігація Chromium заблоковані. Тому в базовий Word-звіт **не внесено вигаданий результат** `17 passed`; матеріали локального контролю, якщо є, позначено окремо.

## Уточнення щодо стабільності

1. `#table1`, `#range`, `#finish`, `#uploaded-files`, `#mce_0_ifr` — це технічні ідентифікатори елементів стенду, не класи оформлення; у відповідних місцях немає доступних семантичних міток.
2. Два прапорці не мають відмінних назв, тому `nth(0)`/`nth(1)` потрібні для перевірки саме першого/другого прапорця.
3. На сторінці завантаження вибрано перше доступне посилання. Якщо зовнішній стенд містить порожній файл, перевірку доцільно прив'язати до конкретного непорожнього тестового файлу після дослідження стенду.
4. Якщо TinyMCE завантажується повільно, у фреймі перевіряється видимість редагованої області; час локального очікування змінюй у конкретному assert, а не через паузи.
